# מודעות עיצובישי ← Google Drive

עורך הפרסומת (`studio/?p=ad`) ← Edge Function `ads-drive` ← Google Apps Script (`Code.gs`, רץ בחשבון של הושעיה) ← תיקיית "מודעות עיצובישי".
למה Apps Script ולא service account: לחשבון service account אין מקום בדרייב אישי (Gmail), אז הוא לא יכול לשמור קבצים בתיקייה של הושעיה.

**מי משתמש (S-193):** הושעיה (מנהל, כניסת מנהל) **וגם כל שותף עם קוד** מ-`studio_ai_codes` (פעיל ולא פג תוקף — אותה בדיקה כמו ב-`ai-image`).
- כולם רואים את כל הקבצים בתיקייה (📂 הדרייב בעורך), בלי חשבון גוגל — התמונות הקטנות נשלפות בשרת.
- שותף שומר תמיד ל-`שותפים/<השם שלו>/` (נוצרת לבד). מנהל בוחר: התיקייה הראשית או תת-תיקייה.
- מחיקה (לפח של הדרייב): מנהל — הכול; שותף — רק מה שהוא יצר. כל קובץ/תיקייה שנוצרים מקבלים description שמתחיל ב-`by:<מי>` (`by:admin` או `by:p-<hash של הקוד>` — הקוד עצמו לא נשמר בדרייב ולא מגיע ל-Apps Script). קבצים שהועלו ידנית (בלי תג) — רק מנהל מוחק.

## התקנה חד-פעמית
1. https://script.google.com → **פרויקט חדש** → למחוק את מה שיש ולהדביק את `Code.gs`. לשמור.
2. למעלה לבחור את הפונקציה **setup** → **▶ הפעלה** → לאשר הרשאות (דרייב, וגישה לשירות חיצוני — לתמונות הקטנות). ביומן מופיע הטוקן — להעתיק.
3. **פריסה (Deploy) → פריסה חדשה → Web app**: Execute as **Me**, Who has access **Anyone** → Deploy. להעתיק את ה-**Web app URL**.
4. Supabase → Edge Functions → Secrets: `DRIVE_ADS_URL` = הכתובת, `DRIVE_ADS_TOKEN` = הטוקן.

שינוי ב-`Code.gs` = לעדכן בפרויקט ב-script.google.com ו-**Deploy → Manage deployments → Edit → New version** (הכתובת נשארת). אם נוספה הרשאה — להריץ שוב `setup` פעם אחת.
עד שהחיבור מוגדר — העורך מציג "החיבור לדרייב עוד לא הוגדר" עם קישור לכאן. התבניות המוכנות עובדות גם בלי דרייב.

## הפעולות (`ads-drive` → `Code.gs`)
| פעולה | מה | מי |
|---|---|---|
| `status` | האם מוגדר (נענה ב-`ads-drive`, בלי Apps Script) | כולם |
| `browse {folderId?, pageToken?}` | תיקיות (רק בעמוד הראשון) + 30 תמונות בעמוד, כל אחת עם `thumb` (dataURL ≤60KB, 240px) או null; `path` לפירורי לחם; `next` לעמוד הבא; לשותף גם `myFolder` | כולם |
| `file_get {id}` | קובץ אחד כ-base64 (עד 25MB) | כולם |
| `list` | התמונות בתיקייה הראשית (S-190) | כולם |
| `save {name, dataUrl, note, folderId?}` | מודעה גמורה PNG/JPEG. `folderId` רק למנהל | כולם (שותף ≤30 שמירות בשעה) |
| `templates` | תיקיות `תבנית – …` בראשית ובתיקיות השותפים, עם `preview` (dataURL), `mine`, `canDelete`, `where` | כולם |
| `template_get {id}` | `template.json` + רשימת הקבצים בתיקייה (`id`,`name`) — הדפדפן מביא כל תמונה ב-`file_get` | כולם |
| `template_save` | בכמה קריאות, ראו למטה | כולם (שותף ≤30 בשעה) |
| `template_delete {id}` · `file_delete {id}` | לפח. `not_owner` אם לא שלכם | מנהל / היוצר |

כל `id` נבדק שהוא בתוך "מודעות עיצובישי" (הולכים למעלה בעץ) — אי אפשר לקרוא או למחוק שום דבר אחר בדרייב.
הגבלת קצב לשותף: טבלה `studio_drive_log` (`supabase/sql/2026-11-24_ads_drive.sql`). עד שהיא קיימת — לא חוסמים.

## תבנית מודעה — הפורמט
תבנית = **תיקייה** `תבנית – <שם>`:
```
תבנית – מבצע חנוכה/
  template.json      ← כל השכבות
  01-<שם>.jpg|png|webp ← קובץ לכל תמונה (באיכות המקורית כשאפשר; PNG כשיש שקיפות או QR)
  02-…
  preview.jpg        ← תצוגה מקדימה, הצלע הארוכה 600px
```
`template.json`:
```json
{
  "version": 1,
  "kind": "itzuvishi-ad-template",
  "title": "מבצע חנוכה",
  "fmt": "post",                      // post | story | wide | a4  (AD_FMTS)
  "bg": "#0A2A5C",                    // צבע הרקע
  "units": { "w": 200, "h": 200 },    // יחידות העורך: רוחב תמיד 200, גובה לפי הפורמט
  "layers": [                         // מלמטה (ראשון) למעלה (אחרון) — זה סדר הציור
    { "k": "img", "file": "01-רקע.jpg", "name": "רקע", "x": 100, "y": 100, "w": 200, "rot": 0 },
    { "k": "text", "text": "30%", "font": "Fredoka", "color": "#0A2A5C", "outline": "none", "x": 52, "y": 93, "fs": 31, "rot": -8 }
  ],
  "files": [ { "file": "01-רקע.jpg", "name": "רקע", "qr": "https://…?(רק ל-QR)", "w": 1080, "h": 1080 } ],
  "fonts": ["Fredoka"],
  "created": "2026-11-24T…", "app": "studio-v1.76"
}
```
- שכבה נשמרת **עם כל השדות שלה** כמו שהם בעורך (`AD.layers`), רק `src`/`si` (מזהה התמונה בזיכרון) מוחלפים ב-`file`, ו-`id` לא נשמר. `x`,`y` = מרכז השכבה; `w` = רוחב תמונה (הגובה לפי יחס הקובץ); `fs` = גודל הכיתוב; `rot` = סיבוב במעלות; `outline` = צבע קו או `none`. שדות שיתווספו לעורך בעתיד (למשל צורת תמונה) נשמרים ונטענים בלי שינוי בפורמט. שדות שכבות (S-197): `hid: true` = מוסתרת (לא מצוירת בהורדה/בתצוגה, נשארת בעיצוב), `lock: true` = נעולה בעורך, `nm` = שם שנתנו לכיתוב.
- `files` = כל התמונות במודעה בסדר שלהן (`AD.img`), גם תמונה שאין לה שכבה.
- פתיחה: כל התמונות נטענות, השכבות נבנות מחדש, הפורמט והרקע מתחלפים — הכול נכנס ל-↶ ("חזרה צעד"). נבדק: שמירה → פתיחה → אותו ציור בפיקסלים (הפרש זניח מ-JPEG).

### שמירה בכמה קריאות (`template_save`)
1. `{step:'begin', title, overwrite?, folderId?}` → `{folderId}` של תיקייה זמנית `⏳ תבנית – <שם>` (לא מוצגת). אם יש כבר תבנית בשם הזה: `exists` + `canOverwrite` (העורך שואל "לשמור במקומה?" ושולח שוב עם `overwrite:true`).
2. `{step:'file', folderId, name, dataUrl}` — לכל תמונה (קריאה לכל קובץ, כך שתבנית גדולה לא נתקעת במגבלת גודל הבקשה).
3. `{step:'finish', folderId, json, preview, overwrite?}` — כותב `template.json` ו-`preview.jpg`, נותן את השם הסופי, ואם דורסים — הישנה עוברת לפח. שמירה שנקטעה לא שוברת תבנית קיימת; תיקיות זמניות ישנות (מעל שעה) נמחקות בשמירה הבאה של אותו אחד.

### תבניות מוכנות (בלי דרייב)
`studio/ads/templates/<id>/` — אותו פורמט, נטען ישירות מהאתר (`AD_BUILTIN` ב-`studio/index.html`, `AD_TPL_V` = גרסת מטמון). ב-4 תבניות "שבת ארגון" `file` הוא נתיב יחסי (`../../shabbat-irgun/ideas/pic.jpg`) כדי לא לשכפל את התמונות. "שמירה כתבנית" של תבנית מוכנה יוצרת תיקייה רגילה בדרייב עם עותק של כל הקבצים.
